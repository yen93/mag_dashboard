Invoice Tracking

MAG Metrics dashboard — sales invoices from Xero

The Invoices page on the MAG Metrics dashboard is a single, sortable table of MyAdventure Group's 2026-onwards sales invoices. It is pulled from Xero, matched to the related ActiveCampaign deal, and refreshed automatically every weekday morning — so anyone can check an invoice's status, whether it has been paid, and the event it relates to, without opening Xero.

What the page shows

One row per Xero sales invoice issued from 2026 onwards. Each row carries seven columns:

  • Date of Event — when the booking / event takes place.
  • Company — the client the work is for.
  • AC Deal — the matching ActiveCampaign deal (see below).
  • Invoice no. — the Xero invoice number.
  • Invoice status — Done, Sent, To draft, Void/deleted, or No Fee.
  • Invoice paid? — Yes, No, or No Fee.
  • Invoice issued? — Full, Deposit, Balance, or No Fee.

Every column can be sorted, filtered on its own values, and the whole table is searchable — the same controls as the Buyer Sheet page.

Where the data comes from

The page draws on three systems, and only ever reads from the external ones:

  • Xero — the source of the invoices. The sync is strictly read-only; nothing is ever created, changed or voided in Xero.
  • ActiveCampaign — supplies the matching deal for the AC Deal column, read from a copy of AC deals already held in the dashboard's database.
  • Supabase — the dashboard's own database, which holds a cached copy of the table that the page displays.

The MAG invoice Google Sheet only defined which columns to build — it is not a data source.

How it refreshes each day

A scheduled routine keeps the table current without anyone pressing a button:

  • It runs every weekday (Monday to Friday) at 6am Philippine time.
  • It reads all 2026-onwards sales invoices from Xero and writes them into the Supabase cache.
  • It then matches each invoice to its ActiveCampaign deal and fills the AC Deal column.

Nothing is ever deleted: existing invoices are updated in place and newly-issued ones are added. Because the page always reads the cache (never Xero directly), it loads instantly.

How each column is worked out

Most columns come straight from Xero; a few are read out of the invoice's description text:

  • Invoice no. / status / paid? — taken directly from the Xero invoice.
  • Date of Event — Xero has no event-date field, so this is read from the invoice's line-item text (the first written date, e.g. “5 March 2026”).
  • Company — taken from the invoice reference (the part before the “_”), because the billing contact is often a speaker bureau rather than the client.
  • Invoice issued? — read from the line-item text (Deposit / Final / Balance), or “Full” otherwise.

The AC Deal column

There is no built-in link between a Xero invoice and an ActiveCampaign deal, so the two are matched. A deal is only attached when both of these hold:

  • the same company, and
  • the deal's event date is within 7 days of the invoice's event date (using the AC Event Date field, or the date in the deal title).

Requiring the dates to agree keeps repeat clients honest — Vistage, for example, has 137 deals, so a deal is only shown when the dates genuinely line up. When nothing matches confidently, the cell is left blank rather than guess.

Figure 3 — A deal title is shown only when the company and the event dates both line up.

Why some cells are blank

Blank cells are deliberate — the system prefers an empty cell to a wrong one.

  • Date of Event is blank when the invoice is an add-on charge — a travel reimbursement, books, a deposit, or an allowance — whose text contains no event date.
  • AC Deal is blank when there is no matching deal for that company/event, when the dates don't line up within 7 days, or when the invoice has no event date to match on.

The data fills out further as Xero descriptions and ActiveCampaign deals are kept complete and consistent.

How it's built

The feature is a small, self-refreshing pipeline. Each part has one job:

  • Xero Accounting API (read-only) — the source of the sales invoices.
  • Daily routine — a scheduled Claude Code cloud agent that runs Monday to Friday at 6am PH, pages through the invoices, and loads them into the cache.
  • Supabase (PostgreSQL) — stores the cached table invoice_tracking the page reads, plus the mirror of ActiveCampaign deals used for matching.
  • Matching step — a database query that attaches the best ActiveCampaign deal to each invoice by company and event date.
  • Dashboard — a Node.js / Express service that serves the Invoices page, a plain HTML/CSS/JS page reusing the shared sortable-table component.

Tech stack

  • Xero Accounting API — invoice source (read-only)
  • ActiveCampaign deals, mirrored in Supabase — AC Deal matching
  • Supabase (PostgreSQL) — the cache database
  • Claude Code scheduled routine (cloud agent) — the daily sync
  • Node.js / Express — the dashboard server
  • Plain HTML, CSS and JavaScript — the page and its table
  • Google Cloud Run — hosting
