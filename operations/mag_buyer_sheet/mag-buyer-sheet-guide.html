MAG Buyer Sheet

Live buyer analysis on the dashboard, from ActiveCampaign + AI enrichment

The MAG Buyer Sheet is a live version of the Buyer Analysis spreadsheet, built straight into the metrics dashboard. It lists every won deal as a buyer record — the same 17 columns as the 2026 and 2027 sheets — and keeps itself up to date automatically from ActiveCampaign and an AI web-search step, so no one has to maintain it by hand.

What it shows

The Buyer Sheet lists one row per won deal — every booked or delivered program — with the same 17 columns as the 2026 and 2027 Buyer Analysis tabs:

  • The booking: Year, Date of Event, Company, Direct/Indirect, Program Delivered, Audience Size and Value (AUD).
  • The company: Industry and Business Size.
  • The people: the initial point of contact (name, email, job title, seniority) and the Key Decision Maker (name, email, job title, seniority).

You can sort any column, search across the whole table, and filter each column individually — the same controls as the Sales pipeline table.

How the data flows

Three sources feed a single scheduled job, which writes one cache table that the dashboard reads. The dashboard itself never calls ActiveCampaign or OpenAI — it only reads the pre-built table, so the page stays fast.

Figure 1 — Sources feed a scheduled job that fills one cache table the page reads.

What happens each day

A scheduled job runs every weekday (Monday to Friday, 6am Philippine time) and does three things in order:

  1. Base upsert — refreshes the straightforward columns (company, program, value, contact) for every won deal.
  2. Reconcile status — any deal that is no longer "won" is tagged (lost / open / removed) and time-stamped, but kept in the table rather than deleted.
  3. Enrich candidates — fills the richer columns for new, changed, or not-yet-enriched rows.

It is incremental: rows that are already complete and unchanged are skipped, so each day only touches what actually moved.

Figure 2 — The three phases of a single daily run.

Where each column comes from

Each column is filled from the best available source:

  • ActiveCampaign provides the deal and contact facts — event date, audience size, direct/indirect, job title, industry, company, value and the contact's name and email.
  • An AI web-search step fills the details that aren't in the CRM — Business Size, Seniority and the likely Key Decision Maker.
  • The deal title is parsed for the Program Delivered and the Year (and as a fallback for the event date and direct/indirect).

Figure 3 — The three sources behind the 17 columns.

How enrichment decides what to do

For every won deal, each run makes a simple decision so it only spends effort (and AI cost) where it's needed:

  • If the row is already enriched and unchanged, it's skipped — no AI call.
  • If a company can't be verified after two tries, it's parked and left blank rather than guessed.
  • The AI step never guesses — it returns nothing when it can't confirm a fact from a reputable public source.
  • If no distinct decision-maker is found, the Key Decision Maker defaults to the enquiry contact.

How it's built

The pipeline

  • ActiveCampaign (CRM) — the system of record for deals, contacts and their custom fields.
  • Supabase (database) — holds a mirror of the CRM's won deals and the mag_buyer_sheet cache table the page reads.
  • Scheduled edge function — a small program (buyer-sheet-sync) that runs on a timer, gathers the data from the sources, and writes the cache table.
  • AI web search — an OpenAI model with web search that fills the enrichment columns.
  • Dashboard — the metrics site that simply reads and displays the cache table.

Tech stack

  • ActiveCampaign REST API (CRM data).
  • Supabase — PostgreSQL database, a scheduled Edge Function (Deno/TypeScript), and pg_cron for the weekday schedule.
  • OpenAI gpt-4o-mini with the web-search tool for enrichment.
  • The dashboard: plain HTML/CSS/JavaScript with a small Node/Express API, hosted on Google Cloud Run.

Finding and reading the page

  • Open the dashboard and click the Buyer Sheet tab.
  • While the AI enrichment is still filling in, the page shows a "partial" badge; it turns to "live" once everything that can be enriched has been.
  • The lost / open / removed status and the "lost on" date are tracked in the database for reporting, but are intentionally not shown on the page.
