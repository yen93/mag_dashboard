The MAG Metrics dashboard now signs you in without a password. You enter your company email, we send a short code to your inbox, and you type that code in to get straight to the dashboard — nothing to remember, nothing to share.

Signing in, step by step

Signing in takes two short steps and no password.

Figure 1 — The two steps you take: enter your email, then enter the code we send you.

  1. Open the dashboard and enter your @myadventuregroup.com.au email, then click Send code.
  2. Check your inbox for a 6-digit code (the subject line starts with the code). It comes from julienne@myadventuregroup.com.au.
  3. Type the code into the Code field and click Sign in. You go straight to the dashboard.

Need another one? Click Resend code. Used the wrong address? Click Use a different email to start over.

Who can sign in

  • Anyone with an @myadventuregroup.com.au email address can sign in — there is no separate account to set up first.
  • Most people sign in as a viewer. A small allowlist keeps admin access for specific addresses.
  • Email addresses on any other domain are turned away before a code is ever sent.

How the code keeps things secure

The one-time code is designed so it can’t be reused or guessed:

  • Each code is 6 digits and valid for 10 minutes, then it stops working.
  • A code can be used only once — signing in consumes it.
  • Requesting a new code cancels the previous one.
  • After 5 wrong attempts a code is locked, so it can’t be guessed.
  • Codes are never stored in plain text — only a one-way scrambled (hashed) version is kept, so even the database never holds the real code.

How it’s built

Here is the whole picture, from the login page to the signed-in session. Each part has one job.

Figure 2 — The pieces behind the sign-in and how a request flows through them.

The pipeline

  • Login page (login.html + app.js) — the two-step email / code form you see in the browser.
  • Dashboard API (Express, on Google Cloud Run) — two endpoints: one to request a code, one to verify it.
  • Supabase (PostgreSQL) — stores each code as a hashed, time-limited, single-use record and checks it when you sign in.
  • Gmail (SMTP) — sends the code email from julienne@myadventuregroup.com.au.
  • Session token (JWT) — once a code checks out, the server issues a token your browser keeps; it’s what proves you’re signed in on every page.

Tech stack

  • Node.js + Express API
  • Plain HTML / CSS / JavaScript front end (no build step)
  • Supabase (PostgreSQL) for code storage
  • Gmail SMTP via Nodemailer for delivery
  • JSON Web Tokens (JWT) for the signed-in session
  • bcrypt for hashing the codes
  • Google Cloud Run for hosting; Google Secret Manager for credentials

If something goes wrong

  • No email arrived? Check your spam / junk folder first. The code comes from julienne@myadventuregroup.com.au. Wait a few seconds, then use Resend code.
  • “Invalid or expired code”? The code may be older than 10 minutes or already used — request a fresh one.
  • Locked out after several tries? Request a new code and enter it carefully.
  • Turned away at the email step? Make sure you’re using your @myadventuregroup.com.au address.
