2. EMAIL HTML QUOTED-PRINTABLE "=20" & PHANTOM TABLE CELL FIX
--------------------------------------------------------------------------------
* Problem / Context:
  When inspecting the received digest email (`email_html.txt`), multiple `=20` characters
  and phantom `<tbody><tr><td> =20 </td></tr>` table rows appeared across the email layout.

* Root Causes Identified:
  1. Quoted-Printable Encoding (RFC 2045):
     In email MIME transmission, any trailing whitespace or space character at the end of
     a line before a newline is encoded as `=20` (0x20 = ASCII space) to prevent mail transfer
     agents from stripping whitespace. Multiline template literals left trailing spaces on blank lines.
  2. Gmail HTML Table Auto-Correction:
     Multiline template literals introduced newline and space indentation directly inside `<table>`
     before `<tr>` tags. Because loose text or whitespace directly under `<table>` is invalid HTML,
     Gmail's HTML parser repaired it by creating anonymous table rows/cells containing the whitespace:
     `<tbody><tr><td> =20 </td></tr>`.

* Technical Changes in `supabase/functions/monitoring-health-digest/index.ts`:
  - Compacted Table Row Generation:
    * Refactored `${issueCards}` and `${summaryRowsHtml}` loop generators to produce compact
      inline `<tr><td style="...">...</td></tr>` rows without leading or trailing newlines.
  - Added HTML Sanitizer (`sanitizeEmailHtml`):
    * Iterates through all lines and runs `.trimEnd()` to eliminate trailing line spaces,
      preventing quoted-printable from emitting `=20`.
    * Collapses inter-tag whitespace between all table tags using regex:
      `.replace(/>\s+</g, "><")`
    * Ensures zero stray text or newlines exist inside `<table>`, `<thead>`, or `<tbody>`.
  - Cleaned SMTP Payload:
    * Passed sanitized HTML into `client.send({ ... })`.
    * Removed `content: "auto"` so denomailer sends pure, properly encoded HTML.
