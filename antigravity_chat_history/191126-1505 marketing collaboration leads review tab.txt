2. BACKEND API, PERMISSIONS & STATUS MAPPING
--------------------------------------------------------------------------------
* Problem / Context:
  Unlike `alternate_leads` and `auto_found_educ_leads` (which use `bigint` IDs
  and free-text `status`), `public.collaboration_leads` uses a `uuid` primary
  key and enforces a CHECK constraint on `outreach_status`:
  `('new', 'reviewing', 'approved', 'contacted', 'replied', 'collaborated',
  'rejected', 'do_not_contact')`.

* Technical Changes:
  - Updated `server/users.js`:
    - Added `COLLAB_LEADS_REVIEW_EMAILS`:
      `cloverly@myadventuregroup.com.au`, `julienne@myadventuregroup.com.au`,
      `james@myadventuregroup.com.au` (confirmed via `public.organization_users`).
    - Exported `canReviewCollabLeads(email)`.
  - Created `server/metrics/collaboration-leads.js`:
    - `getCollaborationLeads()`: queries `public.collaboration_leads` ordered by
      `COALESCE(discovered_at, created_at) DESC, brand_name ASC`, left-joining
      the latest `action = 'set'` entry from `public.collaboration_leads_review_log`.
      Includes a `42P01` (undefined_table) fallback so the page works cleanly
      even before the optional audit-log migration is manually applied.
    - `setCollaborationLeadReview(id, decision, by)`: maps UI decisions to the
      existing `outreach_status` CHECK constraint values without altering
      `collaboration_leads`:
        * `'send'` -> `'approved'` (logs `'Send intro'`, `action='set'`)
        * `'skip'` -> `'rejected'` (logs `'skip'`, `action='set'`)
        * `null`   -> `'new'`      (logs `null`, `action='reset'`)
      Restricts updates to editable statuses (`new`, `reviewing`, `approved`,
      `rejected`, `do_not_contact`) so leads already in `contacted`, `replied`,
      or `collaborated` cannot be overwritten.
  - Updated `server/index.js`:
    - Added `GET /api/marketing/collaboration-leads` (uncached, returns
      `canReview` per user; automatically blocked for `restricted` partner
      accounts by the existing `marketing` router middleware).
    - Added `POST /api/marketing/collaboration-leads/:id/review` with UUID
      regex validation, `canReviewCollabLeads` 403 gate, and decision validation.
