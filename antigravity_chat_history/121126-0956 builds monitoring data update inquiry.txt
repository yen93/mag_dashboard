1. INVESTIGATION: BUILDS MONITORING DATA FEED & SCHEDULE MECHANISM
--------------------------------------------------------------------------------
* User Query / Context:
  Inquiry on whether there is an Edge Function that automatically updates the data
  displayed in `builds_monitoring` (DB Automations) on schedule.

* Investigation & Code Analysis:
  - Frontend Client (`public/builds_monitoring.html`):
    - Fetches telemetry data on page load from `/api/operations/db-automations`.
    - Auto-refreshes every 2 minutes in the client via `setInterval(loadAutomations, 120000)`.
    - Offers manual fresh fetch with `loadAutomations(true)` triggering `?fresh=1`.
  - Backend API Endpoint (`server/index.js` & `server/metrics/db-automations.js`):
    - Handled by Express endpoint `GET /api/operations/db-automations`.
    - Caches results for 60 seconds unless `?fresh=1` is provided.
    - Directly queries PostgreSQL system tables in real time:
      * `cron.job` joined with `cron.job_run_details` via lateral query to get
        `jobid`, `schedule`, `run_status`, `start_time`, `end_time`, `return_message`.
      * `net._http_response` to inspect asynchronous HTTP responses from `pg_net`
        calls (`status_code`, `error_msg`, `content`, `created`).
    - Synthesizes runtime telemetry with the in-code `AUTOMATIONS_CATALOG` (34 automations)
      to extract row counts, durations, and health statuses.
