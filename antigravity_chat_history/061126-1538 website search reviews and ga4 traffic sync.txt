  `claudegwscli-502400.analytics_363754280` could supply "Website sessions" for

* Findings:

    for FY22–FY26 or Jul–Sep 2026.

    retains full session history back to April 2023, is the authoritative source.

3. UPSERT-ONLY GA4 WEBSITE TRAFFIC SNAPSHOT TABLE & WEEKLY SYNC
--------------------------------------------------------------------------------
* Problem / Context:
  Needed a durable, append/upsert-only Supabase table and weekly Edge Function
  to store per-FY "Website sessions" and "Visits from AI tools" from the GA4
  Data API (`properties/363754280:runReport`), never truncating or deleting rows.

* Technical Changes:
  - `supabase/migrations/20261106170000_create_ga4_website_traffic_snapshots.sql`:
    * Created `public.ga4_website_traffic_snapshots` with composite PK
      `(snapshot_date, fy_end)` and columns `fy`, `fy_start`, `fy_end_date`,
      `website_sessions`, `ai_tool_visits`, `ai_sources_breakdown` (`jsonb`),
      and `synced_at`.
    * Added a `BEFORE DELETE` trigger (`trg_prevent_ga4_traffic_snapshots_delete`
      -> `public.prevent_ga4_website_traffic_snapshots_delete()`) that raises an
      exception on any `DELETE` so rows can never be deleted.
    * Created `public.reload_ga4_website_traffic_snapshots(_rows jsonb, _snapshot_date date)`
      (`SECURITY DEFINER`) which strictly performs `INSERT ... ON CONFLICT (snapshot_date, fy_end) DO UPDATE`.
    * Seeded initial baseline rows (`snapshot_date = '2026-11-06'`) for FY22–FY27.
  - `server/metrics/marketing-website-search.js`:
    * Added `TRAFFIC_SNAPSHOT_SQL` (`SELECT DISTINCT ON (fy_end) ... FROM public.ga4_website_traffic_snapshots ORDER BY fy_end, snapshot_date DESC, synced_at DESC`)
      and wired `sessions` and `aiVisits` onto `byFy` and `total`.
  - `public/website_search.html`:
    * Switched `TOP_CARDS` "Website sessions" to `kind: 'live', key: 'sessions'`
      and `BOTTOM_CARDS` "Visits from AI tools" to `kind: 'live', key: 'aiVisits'`
      with `GA4_TRAFFIC_FALLBACK` so both cards update across FY selections.
