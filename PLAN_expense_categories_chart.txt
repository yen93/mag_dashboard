--------------------------------------------------------------------------------
0. TL;DR / WHAT YOU ARE BUILDING
--------------------------------------------------------------------------------
Add ONE new card to the ROI tab (public/roi.html) below the existing
"Revenue vs spend by month" and "AC pipeline" charts: a HORIZONTAL BAR chart
titled "Where the spend goes" showing the top ~8 expense categories for the
selected financial year, with everything else rolled into an "Other" bar. It
re-renders on FY change and honours the existing "Exclude owner wages" toggle.

Data = the Xero P&L expense accounts (expense + cost-of-sales accounts), grouped
by Australian financial year (END-year: FY25 = Jul 2024–Jun 2025). Stored as a new
STATIC seed table (per-FY annual totals). Build is: (1) create+seed table,
(2) add a backend query to the ROI endpoint, (3) add the chart to the page.

IMPORTANT TERMINOLOGY NOTE: these are NOT "cost centers". A cost center is a
department/unit (Admin, IT, …) tracked via Xero "tracking categories" — MAG has
only one tracking category ("Salesperson" → "Sam") and does NOT track spend by
department. So the correct label is "expense categories" / "where the spend goes"
(Xero GL account names), not "cost centers". Use that wording in the UI.

1. CONTEXT — how this app & the ROI tab work (so you don't have to re-discover)
--------------------------------------------------------------------------------
- Plain HTML/CSS/JS frontend in public/ (NO build step, NO bundler) + an Express
  API in server/. One HTML file per screen. Charts use Chart.js vendored at
  public/vendor/chart.umd.min.js. ESM on the server ("type":"module").
- Supabase (Postgres) is the data source. Project ref: aivitcomiywiysrfwqxt
  (name "MAGTestProject"). Server reads it via server/providers/supabase.js's
  q(sql) helper (pooled pg, SSL rejectUnauthorized:false).
- The ROI tab:
    * Page:     public/roi.html  (self-rendering; inline <script>)
    * Endpoint: GET /api/marketing/roi
    * Metric:   server/metrics/marketing-roi.js  (exports getMarketingRoi())
- marketing-roi.js shape: it runs a few SQL queries with q(), wraps each result
  list in section(data, meta) from server/lib/metric.js, and returns:
      { asOf, defaultFy, total, rows, byMonth, pipelines }
  where rows.data is the per-FY array (each row has: fy, fyEnd, revenue,
  hasRevenue, opEx, cos, totalSpend, hasSpend, ownerWages, dealsWon/Open/Lost,
  wonValue, roi). YOU WILL ADD a new `categories` section to this payload.
- roi.html inline script conventions you will reuse:
    * SEL = selected fy_end (a number) or the string 'all'.
    * currentRow() -> the per-FY row object for SEL (or the summed total for 'all').
    * render() re-renders EVERYTHING on any FY change; call your new render fn there.
    * Chart pattern: keep a module-level chart var, destroy() it, rebuild with
      `new Chart(canvasEl.getContext('2d'), cfg)`. See renderPipeline() and
      renderMonthChart() already in roi.html — COPY THAT PATTERN.
    * Helpers available in app.js (already loaded): themeColors() -> {text,muted,
      grid,surface,border,accent}; fmt(value,'currency') -> "$12,345" ("—" for
      null); monthLabel(). roi.html also defines compactAud(v) -> "$15k"/"$1.5m".
    * The "Exclude owner wages" toggle: var EXCL_OWNER (default true) +
      effSpend(row)/effRoi(row)/effMonthSpend(m) helpers already in roi.html.
- FINANCIAL YEAR convention is END-year, Jul–Jun:
      fy_end = extract(year from d) + (extract(month from d) >= 7 ? 1 : 0)
  Labels are 'FY' || right(fy_end::text, 2)  (e.g. 2025 -> "FY25").

--------------------------------------------------------------------------------
2. KEY DATA FACTS / DECISIONS (read before coding)
--------------------------------------------------------------------------------
(a) SOURCE: Xero P&L, ACCRUAL, ex-GST. For each FY the "spend" accounts are the
    union of the P&L `expense_accounts` (operating expenses) and
    `cost_of_sales_accounts`. We IGNORE income and other-income accounts here.
(b) GRANULARITY: PER-FY annual totals are enough — the chart is per-FY, so there's
    no need for monthly category data. (This is why the seed below is small.)
(c) COVERAGE: Xero's API only exposes the current + 3 prior financial years, so we
    only have FY24, FY25, FY26, FY27. FY27 is PARTIAL (Jul–Oct 2026, year-to-date).
    FY22/FY23 have NO P&L (same limit as the rest of the ROI tab) — the chart
    should simply render empty / "No Xero P&L for this FY (pre-FY24)" for those,
    mirroring how the spend card already behaves (row.hasSpend === false).
(d) "OTHER" RECONCILIATION: do NOT seed every tiny account. Seed only the top ~12
    accounts per FY (below). At render time compute:
        Other = (that FY's authoritative total spend) − (sum of the named bars shown)
    The authoritative total spend per FY is ALREADY on the page as
    row.totalSpend (and effSpend(row) when owner wages are excluded). This makes
    the chart total always reconcile to the "Total spend" KPI card, and the
    long tail + any negative accrual lines fall into Other automatically.
(e) OWNER-WAGES TOGGLE INTERPLAY: two category rows are owner comp —
    "Wages - James & Mia" and "Super - James & Mia". When EXCL_OWNER is true
    (the default), DROP those two bars and compute Other against effSpend(row)
    (which already excludes owner wages). When false, include them and use
    row.totalSpend. This keeps the chart consistent with the rest of the tab.
(f) NEGATIVE amounts exist in raw accrual P&L (year-end reversals). None of the
    TOP-12 seed rows below are negative, so you can ignore sign for the bars; the
    negatives live in the tail and net into Other via the reconciliation in (d).
(g) STATIC DATA: this is a one-time seed (like xero_expenses_monthly today — the
    ROI tab's expenses are a static Xero P&L load, refresh routine still pending).
    A future refresh would re-pull these per-FY account breakdowns from the Xero
    P&L (MCP get_profit_and_loss, one call per FY). Out of scope for this build.

3. STEP 1 — CREATE + SEED THE TABLE (Supabase / Postgres)
--------------------------------------------------------------------------------
Run as a migration (preferred) or plain SQL against the Supabase project. Table
is per-FY, per-account. `kind` distinguishes operating expense vs cost of sales
(useful if you later want to colour/segment by it; not required for the basic bar).

--- DDL -------------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS public.xero_pnl_accounts_fy (
  fy_end       integer     NOT NULL,          -- AU FY end year (END-year): 2025 = FY25
  account_name text        NOT NULL,          -- Xero GL account name (verbatim)
  kind         text        NOT NULL           -- 'expense' | 'cost_of_sales'
                 CHECK (kind IN ('expense','cost_of_sales')),
  amount       numeric     NOT NULL,          -- AUD, ex-GST, accrual, annual total for the FY
  synced_at    timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (fy_end, account_name)
);
COMMENT ON TABLE public.xero_pnl_accounts_fy IS
  'Per-financial-year Xero P&L spend accounts (expense + cost_of_sales), for the ROI tab "Where the spend goes" chart. STATIC seed from the Xero P&L via MCP (top ~12 accounts per FY; the long tail folds into an "Other" bar computed at render time against xero_expenses_monthly total_spend). END-year FY. FY27 is partial (YTD). Refresh routine pending.';

(b) JS — add a module-level var and a render fn, modelled on renderPipeline().
    Put TOP_N = 8 (that's the "top ~8"). Place this near renderPipeline():

    var _catChart = null;
    var CAT_TOP_N = 8;
    function renderCategories() {
      var row = currentRow();
      var src = (ROI.categories && ROI.categories.data) || [];
      // Gather the category rows for the selection.
      var rows;
      if (SEL === 'all') {
        // Sum each account across all FYs.
        var byAcct = {};
        src.forEach(function (c) {
          if (!byAcct[c.account]) byAcct[c.account] = { account: c.account, amount: 0, isOwnerWage: c.isOwnerWage };
          byAcct[c.account].amount += c.amount;
        });
        rows = Object.keys(byAcct).map(function (k) { return byAcct[k]; });
      } else {
        rows = src.filter(function (c) { return c.fyEnd === SEL; })
                  .map(function (c) { return { account: c.account, amount: c.amount, isOwnerWage: c.isOwnerWage }; });
      }
      // Honour the "exclude owner wages" toggle: drop those categories.
      if (EXCL_OWNER) rows = rows.filter(function (r) { return !r.isOwnerWage; });
      rows.sort(function (a, b) { return b.amount - a.amount; });

      // If there's no spend data for this FY (FY22/FY23), clear the chart.
      var hasData = row && row.hasSpend && rows.length;
      if (!hasData) { if (_catChart) { _catChart.destroy(); _catChart = null; } return; }

      // Top N + "Other" reconciled to the authoritative total spend on the page.
      var top = rows.slice(0, CAT_TOP_N);
      var authTotal = EXCL_OWNER ? effSpend(row) : row.totalSpend; // see roi.html helpers
      var shownSum = top.reduce(function (a, r) { return a + r.amount; }, 0);
      var other = Math.max(0, Math.round(authTotal - shownSum));
      var labels = top.map(function (r) { return r.account; });
      var data = top.map(function (r) { return r.amount; });
      if (other > 0) { labels.push('Other'); data.push(other); }

      var tc = themeColors();
      var cfg = {
        type: 'bar',
        data: {
          labels: labels,
          datasets: [{
            label: 'Spend',
            data: data,
            backgroundColor: labels.map(function (l) { return l === 'Other' ? '#9aa4b2' : '#17a673'; }),
            borderRadius: 4, maxBarThickness: 26,
          }],
        },
        options: {
          indexAxis: 'y', responsive: true, maintainAspectRatio: false,
          plugins: {
            legend: { display: false },
            tooltip: { callbacks: { label: function (ctx) { return fmt(ctx.parsed.x, 'currency'); } } },
          },
          scales: {
            x: { beginAtZero: true, ticks: { color: tc.muted, callback: compactAud }, grid: { color: tc.grid } },
            y: { ticks: { color: tc.muted }, grid: { display: false } },
          },
        },
      };
      if (_catChart) _catChart.destroy();
      var el = document.getElementById('roiCatCanvas');
      if (el) _catChart = new Chart(el.getContext('2d'), cfg);
    }

(c) Wire it into render(): add these two lines alongside the other chart calls

        setChips('catChips', ROI.categories.meta);
