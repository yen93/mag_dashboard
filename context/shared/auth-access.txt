# AUTH & ACCESS — passwordless OTP login + restricted partner role
# (Extracted from CLAUDE.md — the dashboard dev reference. Read this when working on the page/area above.)

- **Auth = passwordless email code (OTP).** No passwords, no user table.
  `login.html` is a two-step form (email → code). `POST /api/request-code`
  accepts any `@myadventuregroup.com.au` email, generates a 6-digit code, stores
  its **bcrypt hash** in Supabase table `dashboard_login_codes` (10-min expiry,
  60s resend throttle, 5-attempt cap — see `server/lib/loginCodes.js`), and
  emails it via Gmail SMTP from `julienne@myadventuregroup.com.au`
  (`server/lib/mailer.js`; logs the code to console when email isn't
  configured). `POST /api/verify-code` checks the code, then `server/users.js`
  derives the user from the email (`userFromEmail`/`isAllowedEmail`; `admin`
  role only for an allowlist, everyone else `viewer`) and `server/auth.js` signs
  the same JWT payload (`{sub,email,name,role}`) with `JWT_SECRET`. Frontend
  keeps the token in `localStorage`; a 401 triggers logout → `login.html`.
  `requireAuth`/`/api/me` and all `/api/*` guards are unchanged.


- **Restricted partner role (2026-11-13).** `server/users.js` `RESTRICTED_DOMAINS`/`RESTRICTED_EMAILS` (simpledigital.net.au + testertwo.myadventuregroup@gmail.com) sign in normally but get `role:'restricted'` and may see ONLY `leads_bookings.html` + `roas.html` (ROAS added 2026-11-13, additional access). **Server is the real gate** (static HTML in `public/` is served to anyone): `requireFullAccess` in `server/auth.js` 403s metrics/sales/operations, ga4-agent, roas/roi assistants and the db/claude/n8n alias routes; the `marketing` router allows restricted users only `/leads-by-source` + `/overview`; the `operations` router no longer has a blanket `requireFullAccess` — it allows restricted users only `/roas` + `/roas/deals` (`RESTRICTED_OPERATIONS_PATHS`), and `/api/roas-assistant` is NOT `requireFullAccess`-gated (restricted users can chat with it; re-gate if unwanted). If either page ever calls another endpoint, add it to `RESTRICTED_MARKETING_PATHS` / `RESTRICTED_OPERATIONS_PATHS` in `server/index.js`. Frontend: `app.js` `isRestrictedUser()`/`landingPage()`/`pageAllowedForUser()`/`RESTRICTED_PAGES`; `initPage` redirects + adds `body.restricted-view` (CSS hides nav) and `renderRestrictedNav()` injects a slim 2-link switcher in the top bar. **Gotcha:** bulk-editing HTML from PowerShell `Get-Content`/`Set-Content` corrupts UTF-8 (em dash) and adds BOM/CRLF — edit via UTF-8-safe tools (`sed -i` is fine). Pages are at `app.js?v=19`.
