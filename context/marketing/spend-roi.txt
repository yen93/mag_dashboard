# (Extracted from CLAUDE.md — the dashboard dev reference. Read this when working on the page/area above.)

  **Spend & ROI drill-down (2026-11-10):** clicking a bar in "Spend by type" opens a modal listing the
  distinct vendor names under that type (names only, no $), via NEW `GET /api/marketing/channel-items` →
  `server/metrics/marketing-channel-items.js` (same `coalesce(type,'Uncategorized')` bucketing as
  `marketing-channel-summary.js` BY_TYPE, so the list matches the bar). The page also has a 6th KPI card
  "Marketing revenue" (first, highlighted) and an Executive X-only "Updated at the close of each season." note.
  **Spend & ROI page (`spend_roi.html` = Marketing sub-tab "Spend & ROI", now LIVE as of 2026-11-05):**
  a self-rendering page (`initPage('marketing')` with no renderFn + `renderMarketingSidebar('spend-roi')` +
  its own `fetchJSON`). **As of 2026-11-05 it calls `renderMarketingHead(true)`** (right after `initPage`,
  before the sidebar) → the shared Marketing head with NO "Sample data" badge; its old bespoke `.sr-head`
  header was removed.
  Same bespoke inline visual layer as `leads_bookings.html`/ROAS (page-local `--mkt-*` tokens, card/KPI
  hover, gradient-active `.segmented`, full-width `.content`). Top: the **standard `#fySeg` FY toggle**
  (All years + FY22–FY27, default FY27), same placement as the Overview. **Three live pieces:**
  (1) **5 KPI cards** — **SAME DB sources as `roi.html`** (brief item #4): fed by **`GET /api/marketing/roi`**
  + **`GET /api/marketing/overview`** (enquiry count only). **Marketing spend** = `row.totalSpend`;
  **Net return** = `marketingRevenue − spend`; **Marketing ROI** = **net ROI %** `(mRev÷spend − 1)` (the
  SAME definition as roi.html's "Net ROI" — the sub-line shows "Return on spend ×"; **deliberately NOT** the
  design mock's gross "218% / incl. influenced 260%" — there's no live "influenced" figure); **Marketing
  CAC** = `spend ÷ dealsWon`; **Cost per enquiry** = `spend ÷ enquiries`. All FY-aware, hand-built (so each
  carries its own vs-prior-FY delta), re-rendered on the `#fySeg` toggle. (2) **"Spend by type"** horizontal
  bar — the **`type` series of `GET /api/marketing/channel-summary`** (the **SAME buckets + DB source** as
  roi.html's Channel Summary "By type" — Wages/Digital Ads/Agency/Software/Tools/Printed Collaterals; brief
  item #5), **summed over the selected FY's calendar months** via a page-local `channelMonthFyEnd()`
  (`'Mon-YYYY'` → AU FY-end). (3) **"Channel results"** table — **5 channels (as of 2026-11-10; was the two
  `channel_list` channels only — Paid, Executive X, Bureau, Tailor, Marketing EDM)**, full design columns
  (Channel / Spend / Enquiries / Cost-per-enquiry / Bookings / Revenue / ROAS total / ROAS ads), from a
  **NEW endpoint `GET /api/marketing/channel-results`** →
  **`server/metrics/marketing-channel-results.js`** (`getMarketingChannelResults`, requireAuth, cached 10 min):
  returns each channel **per FY** (+ an all-years `total` + `defaultFy`), as a row object
  `{fyEnd,fy,paid,execX,bureau,tailor,edm}`. **Paid (Google, Bing, Agency)**
  reuses the canonical **ROAS metric `getRoas()`** (`server/metrics/roas.js`) — Spend = **All-in cost**
  (Google Xero + Bing + Simple Digital/agency), Enquiries = `leads` (won+lost+open), Bookings = `won`,
  Revenue = `wonRevenue`, ROAS total/ads = `roasAllin`/`roasGoogle`. **Executive X** = `public.exec_x_revenue`
  — Bookings = count of engagements (one row/client), Revenue = `sum(revenue)`. **Executive X SPEND** = the Xero
  **"MAG program delivery expenses" account (code 376, cost of sales)** per FY, read from
  `public.xero_pnl_accounts_fy` (no new sync — that cache already holds it). **Caveat:** 376 is MAG's SHARED
  all-programs delivery account (Geocon + all immersive programs, not Exec X only; Xero has no tracking category
  to split it), so Exec X spend OVERCOUNTS and its ROAS total (= revenue ÷ spend) reads low — a deliberate owner
  choice (the Exec X ROI sheet's per-session internal cost is the Exec-X-only alternative, not used here).
  **Executive X ENQUIRIES** = companies (attendees) listed per season in the "Executive X ROI Report" sheet, summed
  by session-date FY (`EXEC_X_ENQUIRIES_BY_FY` in `marketing-channel-results.js`: FY24 21, FY25 23, FY26 23).
  STATIC hardcode (the sheet has no live feed; `exec_x_revenue` holds only the 17 revenue rows) — keep in sync
  with `nurture_events.html`'s `EXEC_X` `attendees`. **The row is LABELLED "Offsite"** in `spend_roi.html`
  (CH_COLOR key + channelRowHtml label); the field name `execX` and the server key are still Exec X.
  **Bureau / Tailor
  (added 2026-11-10)** = enquiries, bookings + won revenue from the **leads-by-source metric**
  (`getMarketingLeadsBySource().leads`, imported into `marketing-channel-results.js` — `ac_indirect_deals`
  split by `is_tailor`), so **these rows reconcile EXACTLY with the Leads & Bookings "By source" table**; the
  FY axis now unions these lead FYs too. (An **Organic** row was added then **REMOVED same day 2026-11-10**
  per the owner — it's no longer in the table or the row object.)
  **Marketing EDM (added 2026-11-10)** = not yet attributed to deals → every column pending.
  **PENDING SENTINEL (as of 2026-11-10):** a column with **no known source** for a channel comes back as the
  string **`'pending'`** (NOT `null`) and the page renders it as the DESIGN_GUIDE §8 red **`pending` chip**;
  `null` stays "—" (a genuine missing value). **Executive X's untracked column (ROAS ads only; spend and enquiries are now sourced — see above) was
  switched `null`→`'pending'`** (so they now show the chip, not "—"); Bureau/Tailor/Organic's
  spend/cost-per-enquiry/ROAS are `'pending'`; Marketing EDM is `'pending'` across the board. Cost-per-enquiry
  is derived client-side (`spend ÷ enquiries`; `'pending'` whenever spend or enquiries is `'pending'`). The
  page's cell helpers (`fmtCur`/`intCell`/`roasCell` + a local `pendChip()`/`PENDING`) render the sentinel.
  **No `app.js` bump** (uses existing globals + the `.chip.warn` class already in `app.css`); no DB/migration/
  secret change. **Responsive**
