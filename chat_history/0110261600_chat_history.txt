--------------------------------------------------------------------------------
ASSISTANT:
Traced the filter UI to the shared renderSortableTable() in public/app.js
(both pages use it via the Buyer Sheet's loadBuyerSheet() and the Sales table).
The column-filter panel is mounted on <body> and, while open, registers a
capture-phase scroll listener on window that called closePanel() directly
(app.js:385). Because it was capture-phase, scrolling the panel's own value
list (.cf-list, which has max-height:240px; overflow-y:auto) also fired that
listener and closed the panel — the bug.

First fix: replaced the direct closePanel scroll handler with an onScroll()
wrapper that ignored scroll events originating inside the panel
(openPanel.contains(e.target)). Updated both the add and remove listener calls
to reference onScroll. Told the user it was shared by both pages and to hard-
refresh since app.js was cached.

ASSISTANT:
Re-examined the flow and CSS. Confirmed .cf-list scrolls at 240px and that the
table sits in a .table-scroll (overflow-x:auto) container. Reasoned the first
patch was logically correct for the reported case, so the most likely causes
were (a) a cached app.js (the HTML referenced "app.js" with no version string,
so browsers/Cloud Run served the stale file) or (b) the user testing the live
Cloud Run site, which still had the old code.

Hardened the fix anyway to cover edge cases:
- Rewrote onScroll() to return early for window/page scroll (document,
  window, documentElement, body) — the panel is positioned to the document
  and scrolls with it, so a page scroll shouldn't close it — and to return
  early for scrolls inside the panel; it now closes only on a genuine
  scroll-away such as the table's horizontal .table-scroll moving the header
  cell out from under the panel.
- Added overscroll-behavior:contain to .cf-list in app.css so wheeling past
  the list's top/bottom doesn't chain into a page scroll (which would have
  closed the panel).
- Cache-busted by bumping the script reference to app.js?v=2 in all five
  pages: sales.html, mag_buyer_sheet.html, marketing.html, operations.html,
  login.html.

Walked the user through the three handler cases (list scroll → stays open;
page scroll → stays open; table sideways scroll → closes) and offered to
deploy.
