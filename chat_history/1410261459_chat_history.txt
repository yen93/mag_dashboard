ASSISTANT (read-only /q investigation):
Concluded: almost certainly MANUAL, not automation-populated. Evidence gathered
from AC (contact field-value rows with cdate/udate/created_by) plus a Supabase
join to get each filled contact's creation date:
 (1) Timing lag — for recent contacts, all real intake/form fields are written
     at contact-creation, but Lead Source (field 20) is a standalone write landing
     days-to-MONTHS later (e.g. contact 15038 PAID-Google Ads set ~4.5 months
     after signup; 14318 ORGANIC ~8 months; 16273 ~4 months). An automation/form
     would stamp it synchronously at submit.
 (2) Each field-20 row is a lone write with cdate==udate (set once, never revised).
 (3) Value semantics — "James prior keynote/relationship", "Referral", "Cold Call",
     "Sam Prior contact", "Other" require human judgement an automation can't derive
     from form/UTM data.
 (4) Low, sporadic fill rate (~40/226 = 18%); a form/automation mapping would fill
     ~100% of its path.
 (5) The bulk of ALL historical values came from a one-time import — thousands of
     field-20 rows stamped within a ~2-minute window on 2021-08-16 (created_by null).
Caveat flagged: did not read the internal action blocks of every automation (the
automation list is ~130 KB and no automation is named for Lead Source), so not a
100% "no automation anywhere" guarantee, but the write fingerprint is decisive.
Offered to inspect the handful of intake/deal automations' blocks for certainty
(stays read-only). Made zero modifications (/q constraint honoured).
