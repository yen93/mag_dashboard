Investigated how Source chips are produced. Found the single source of truth is
metaChips() in public/app.js, which every page calls (via each page's setChips()

    <span class="chip src">SOURCE</span>
as a loud, always-visible chip, while "needs setup"/"partial" chips already used

CSS check: app.css had only .chip.src / .chip.warn / .chip.partial (no base
.chip rule); .kpi cards have no overflow:hidden, so an absolutely-positioned
tooltip won't be clipped.

Made three changes, all in the shared layer so every tab updates at once:

1. public/app.js — Replaced the inline source chip with a new srcInfo(source)
   helper that renders a small circular ⓘ info icon (inline SVG) with an
   accessible wrapper (tabindex=0, role="button", aria-label="Data source: …").
   The source name lives in a hover/focus-revealed <span class="src-tip"> with a
   "SOURCE" label. metaChips() now calls srcInfo(meta.source); the warn/partial
   chips are unchanged.

2. public/app.css — Replaced the .chip.src rule with:
   - .src-info (the 18px circular icon button; accent-soft bg, inverts to solid
     accent on hover/focus; flex:none so it doesn't stretch in inline-flex rows)
   - .src-info-icon, .src-tip (the pop-up: positioned above the icon, themed via
     surface/border/shadow tokens, hidden by default, shown on hover/focus,
     max-width 260px, with a little downward arrow via ::after)
   - .src-tip-label (the small uppercase "SOURCE" caption)
   Works in light and dark via existing CSS variables.

3. All 17 HTML pages — bumped the app.js cache-buster to ?v=8 (versions were
   mixed at v2/v3/v7) with a single sed pass, so browsers fetch the new helper
   after deploy. Verified every page now reads app.js?v=8.

Verification: grepped for leftover "chip src" literals (none remained) and
confirmed srcInfo/src-info references exist only in app.js + app.css.
