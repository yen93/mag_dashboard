ASSISTANT:
Diagnosed: the per-column filter builds its option list (distinctValues) and matches
via textOf(row, col) in public/app.js, which for a column with a `render` strips the
HTML tags from the rendered cell. Since the JC cell's render is now an interactive
<select> (for reviewers), stripping its tags yielded the SAME string for every
interactive cell — all three option labels ("— set tag —", "Could be SEO or Paid Ad",
"Not paid ad / SEO") concatenated — so for-review rows and tagged rows collapsed into
one filter bucket (and sort/search were likewise broken for those cells).

Fix (frontend-only):
- public/app.js: textOf() now honours an optional `column.text(v, row)` accessor and
  uses it for filter/sort/search when present, instead of stripping the render HTML.
  Backward-compatible — no other column sets `text`, and all three consumers
  (distinctValues, the view() filter match via set.has(textOf(...)), and text sorting)
  already route through textOf, so one change covers them.
- public/ac_contact_sources.html: the JC column now supplies `text` →
  tagged → the tag value ("Could be SEO or Paid Ad"); reviewed+cleared →
  "Not paid ad / SEO"; unset/for-review → "—". So the filter now shows three distinct,
  separately-filterable buckets; sort/search behave sensibly.
- Bumped the page's app.js?v=4 → ?v=5 so it reloads the updated app.js.
Verified node --check on app.js. Display-only; no DB/server change; ships with the
already-pending manual Cloud Run redeploy.
