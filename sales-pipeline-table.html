Sales Pipeline Table

Keynotes // Workshops // Immersive (LIV) — MAG Metrics Dashboard

The Sales screen of the MAG Metrics dashboard is now a single, focused working list: the Keynotes // Workshops // Immersive (LIV) pipeline of deals created in 2026. The charts and KPI tiles have been removed so the page does one job well — let you read, search, sort and filter every deal in that pipeline, with the details pulled live from MAG's own systems.

What you see on the page

The page shows one table — every deal in the LIV pipeline that was created in 2026 — with a live count of how many deals are showing. Each row is one deal, with these columns:

  • Created — the date the deal was created.
  • Account — the client organisation.
  • Lead type — inbound or outbound.
  • Primary contact — the person on the deal.
  • Job title — the contact's role (see the section below).
  • Last note and Note date — the most recent note logged against the deal.
  • Owner — the MAG team member who owns the deal.
  • Replied — whether the contact has replied.
  • Status — open, won or lost (shown as a coloured pill).
  • Demo date, Magalog and Proposal — key milestone signals for the deal.

A small chip above the table shows where the data came from — Supabase plus ActiveCampaign when everything is connected.

Searching, sorting and filtering

The table works like a lightweight spreadsheet. There are three ways to narrow it down:

Search

Type in the Search deals… box above the table to keep only rows that match your text anywhere across their columns.

Sort

Click any column heading to sort by that column; click it again to reverse the order. A small arrow shows which column is sorting and in which direction. Dates sort chronologically and numbers sort numerically.

Filter by value (like a Google Sheets filter)

Each column heading has a small filter button (▾). Click it to open a drop-down that lists every distinct value in that column as a checkbox. From there you can:

  • Tick or untick individual values to choose exactly which ones show.
  • Use Select all or Clear to select or deselect everything at once.
  • Type in the drop-down's own search box to find a value quickly in a long list.
  • Filter several columns at once — for example, Owner = a specific person and Status = open.

The filter button highlights while a filter is active, and the deal count above the table updates to show how many rows are currently visible. Filtering, sorting and search all work together.

The Job title column

The Job title column shows the contact's role — for example "Managing Director" or "Executive Assistant". This value lives in ActiveCampaign as part of the link between a contact and their account (the same "Job Title" you see under a contact's General Details, next to their Account). The dashboard reads it live from ActiveCampaign and matches it to each deal by contact.

Some rows may still be blank. That simply means no job title has been recorded against that contact's account in ActiveCampaign. To fill a gap, add the job title on the contact in ActiveCampaign and it will appear on the dashboard the next time the data refreshes.

How it's built

The dashboard is a single, self-contained web service. It is deliberately kept simple — plain, hand-editable web pages on the front, one small server behind them, and the real MAG data pulled in when a page loads.

The pipeline, end to end

  • The page — a plain HTML page (no build step) that draws the pipeline table in the browser and provides the search, sort and filter controls.
  • The server — a small Node/Express service that serves the page and answers a single data request for it, /api/sales/deals.
  • Supabase (primary data) — MAG's database, queried at load time for the core deal columns: created date, account, contact, status, demo date and proposal.
  • ActiveCampaign (enrichment) — called to fill the columns that only live in the CRM: lead type, owner name, latest note, Magalog, and the Job title from the contact's account link.
  • Sign-in — a login step gates the whole dashboard so only MAG staff can see it.
  • Hosting — the service runs on Google Cloud Run and refreshes the deal data on a short cache so the table stays current without hammering the source systems.

Enrichment is best-effort: if ActiveCampaign is briefly unavailable, the table still loads with the Supabase columns rather than failing — the source chip simply notes that some columns are unavailable.

Tech stack

  • Plain HTML, CSS and JavaScript for the page (no framework, no bundler).
  • Node.js with the Express web server.
  • Supabase (PostgreSQL) as the primary data source.
  • ActiveCampaign for CRM contact, deal and note details.
  • JWT-based login for access control.
  • Google Cloud Run for hosting and deployment.

Getting to the page

Open the dashboard and sign in with your MAG credentials, then use the Sales tab at the top. If you have the page open already, do a hard refresh (Ctrl+F5) to make sure you're seeing the latest version.
